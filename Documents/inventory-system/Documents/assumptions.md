# Assumptions — Inventory Management System

These assumptions fill small gaps in the specification. They do **not** change any requirement, business rule or acceptance criterion in the POC specification. No backend, database or server logic is assumed.

## 1. General

| ID | Assumption |
|---|---|
| A-01 | The app is used by a single user in one browser. There is no login, user account or role system (real authentication is out of scope). |
| A-02 | All data lives only in that browser's localStorage. Clearing browser data removes the inventory data. |
| A-03 | The app is designed for desktop and tablet screens. |
| A-04 | Currency is shown only as a display symbol (₹). No tax, GST or accounting calculation is done. |

## 2. Data and Storage

| ID | Assumption |
|---|---|
| A-05 | Each record gets an internal unique `id` generated by the app. Codes (Product Code, Category Code, Supplier Code) are separate user-visible fields. |
| A-06 | Dates are stored in ISO format and shown in a readable local format. |
| A-07 | Sample data (20 products, 5 categories, 5 suppliers) loads only when no saved data exists. A flag in `inventory_settings` records that it was loaded. |
| A-08 | If localStorage data is missing, the app starts with sample data. If data is corrupted or cannot be read, the app shows an error message when saving and does **not** overwrite the saved data. |
| A-09 | Sample transactions are created so that no product's stock is ever negative and each `balanceAfter` is correct. |

## 3. Stock Calculation

| ID | Assumption |
|---|---|
| A-10 | Available Stock is calculated from Opening Stock and recorded transactions. It is not saved as a separate editable number. |
| A-11 | When a product is created, its Opening Stock is recorded as the first transaction of type "Opening" (the spec lists Opening as a transaction type). |
| A-12 | Each transaction stores `balanceAfter`, calculated when it is saved, so the history can be shown without recalculating. |
| A-13 | A Stock Adjustment stores a signed difference (Actual Stock − System Stock). If the difference is zero, nothing is saved and a message is shown. |
| A-14 | Inventory Value uses the product's current master Unit Cost, as the spec states. The Unit Cost entered in Stock In is kept only in that transaction. |

## 4. Master Data

| ID | Assumption |
|---|---|
| A-15 | Deactivating a product, category or supplier is a status change, not a deletion. Records are never removed. |
| A-16 | An inactive category or supplier stays visible on existing products and old transactions, but cannot be chosen for new ones. |
| A-17 | Units of Measure come from a fixed dropdown list: Pieces, Boxes, Packs, Sets, Meters. |
| A-18 | Stock quantities are whole numbers (nonnegative integers). |
| A-19 | Product Code length is limited to 20 characters; code uniqueness is checked case-insensitively. |

## 5. Screens and Behaviour

| ID | Assumption |
|---|---|
| A-20 | Categories and Suppliers use dialogs for add/edit, as the spec allows combining screens. |
| A-21 | The Low Stock Report (INV-11) and Inventory Reports (INV-12) are placed together on the Reports page, using tabs. |
| A-22 | The default page size is 10 records. Users can switch to 5 or 20 (Reports use 10, 20 or 50). |
| A-23 | Deactivation asks for confirmation using an MUI dialog. Success and error messages use MUI Snackbars and Alerts. |
| A-24 | "Today's Transactions" on the dashboard counts transactions whose date is the current local date. |
| A-25 | Invalid forms never save, and a form is cleared after a successful save so it cannot be submitted twice. |
| A-26 | Transaction History is shown newest first by default, and users can change the sort. |
| A-27 | CSV export is created in the browser and downloaded as a file. No server is used. |
| A-28 | The chart library is Recharts (free and commercially usable). |
| A-29 | User-entered text is shown as plain text only (React escapes it by default). |

## 6. Dashboard, Reports and Other Choices

| ID | Assumption |
|---|---|
| A-30 | Dashboard cards count only active products. |
| A-31 | "Low Stock Products" counts products whose status is Low Stock. Out of Stock is counted separately. |
| A-32 | "Today's Transactions" counts Stock In, Stock Out and Adjustment entries dated today. Opening entries are not counted. |
| A-33 | The Current Stock Report shows active products by default, and the Low Stock Report shows active products only. |
| A-34 | CSV files contain all filtered rows, not just the visible page. Text starting with `=`, `+`, `-` or `@` gets a leading apostrophe so spreadsheets do not run it as a formula. |
| A-35 | Transaction ids use the format `TXN-0001`, and each new id is the highest existing number plus 1. |
| A-36 | On Stock Adjustment, the Adjustment Date is set automatically to the time of saving and shown read-only. |
| A-37 | The 50 sample transactions are 30 movements plus 20 Opening entries, one per product. |
| A-38 | The Deactivate action uses a block icon with a tooltip, because records are deactivated and never deleted (BR-018). |
